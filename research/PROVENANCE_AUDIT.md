## 1. Executive Summary

Every empirical artifact generated in FairLens AI (`raw/`, `claims/`, `summaries/`, `processed/`) is cryptographically tied to its exact generating context through immutable SHA-256 digests, Git commit hashes, environment dependency manifests, and parameter records. This guarantees exact reproducibility and non-repudiation of every reported metric.

### 2.2 Experiment Manifest Schema (`research/experiments/runner.py`)
Every experimental condition writes an immutable JSON manifest storing:
- Python runtime version, OS architecture, platform details.
- Exact pip package versions for core dependencies: `scikit-learn`, `fairlearn`, `xgboost`, `shap`, `google-generativeai`, `numpy`, `pandas`.
- Dataset metadata: source URL, raw sample counts, sensitive feature definitions, privileged/unprivileged group encodings.
- Random seeds for train/val/test splits, model initialization, and mitigation calibration.

## 3. Cryptographic Evidence Hashing (SHA-256)

### 3.1 Hashing Methodology
- **Source Location:** `research/evidence/schemas.py` (`AuditEvidence.compute_evidence_hash`)
- **Canonical Serialization:** To ensure hash determinism across platforms and runs:
  1. Floating-point numbers are rounded to 4 decimal places (`round(val, 4)`).
  2. Dictionary keys are sorted alphabetically.
  3. Non-deterministic metadata (timestamps, file paths) are excluded from the hash preimage.
  4. JSON serialization uses compact separators: `json.dumps(obj, sort_keys=True, separators=(",", ":"))`.
  5. The UTF-8 encoded string is hashed with `hashlib.sha256()`.

### 3.2 Paired Integrity Guarantee
Regression test `TestPairedEvidenceIntegrity.test_template_and_llm_share_identical_evidence_hash` verifies that:
1. The hash is deterministic across repeat serializations.
2. The exact same evidence object is supplied to both the deterministic template baseline and the stochastic LLM provider.
3. Hash collisions or discrepancies immediately fail the pipeline.

## 4. Prompt and Parameter Tracking

- **Prompt Registry:** Prompts are version-controlled in `research/llm/prompts/` and registered with explicit IDs (e.g. `combined_audit_v1`, `fairness_audit_v1`, `mitigation_delta_v1`).
- **Ablation Preservation:** Changes to prompt phrasing necessitate a new version identifier (e.g., `_v2`), preventing retrospective alteration of experimental conditions.
- **Deterministic Baseline:** The template baseline (`TemplateExplainer`) uses a fixed rule-based grammar directly populating the exact metrics and attributions from `AuditEvidence`.
